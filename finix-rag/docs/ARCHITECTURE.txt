╔══════════════════════════════════════════════════════════════════════════════╗
║                    SECURITY LAYERS - DEFENSE IN DEPTH                       ║
╠══════════════════════════════════════════════════════════════════════════════╣
║                                                                             ║
║  Layer 1: TRANSPORT SECURITY                                                ║
║  ┌─────────────────────────────────────────────────────────────────────┐    ║
║  │  TLS 1.3 on all connections (Vault, Qdrant, OPA, API)              │    ║
║  │  Certificate rotation every hour (Qdrant auto-refresh)              │    ║
║  └─────────────────────────────────────────────────────────────────────┘    ║
║                                                                             ║
║  Layer 2: AUTHENTICATION                                                    ║
║  ┌─────────────────────────────────────────────────────────────────────┐    ║
║  │  JWT HS256 tokens with expiry (30 min default)                      │    ║
║  │  Token revocation via JTI tracking                                  │    ║
║  │  5 roles: admin, analyst, auditor, teller, readonly                 │    ║
║  └─────────────────────────────────────────────────────────────────────┘    ║
║                                                                             ║
║  Layer 3: AUTHORIZATION (RBAC + ABAC)                                       ║
║  ┌─────────────────────────────────────────────────────────────────────┐    ║
║  │  OPA Rego policies evaluated per request                            │    ║
║  │  Clearance levels: 1=public, 2=internal, 3=confidential, 4=rest.   │    ║
║  │  Tenant isolation: users scoped to their tenant                     │    ║
║  │  Time-based: restricted docs only during business hours             │    ║
║  │  IP-based: block suspicious IP ranges                               │    ║
║  └─────────────────────────────────────────────────────────────────────┘    ║
║                                                                             ║
║  Layer 4: PII PROTECTION                                                    ║
║  ┌─────────────────────────────────────────────────────────────────────┐    ║
║  │  Indian banking PII: Aadhaar, PAN, IFSC, UPI, GST, Phone, Email    │    ║
║  │  Strategy: tokenize before embedding (prevents embedding leakage)   │    ║
║  │  Vault stores token→real mapping (never in vector DB)               │    ║
║  │  Output sanitization: re-mask PII in LLM responses                  │    ║
║  └─────────────────────────────────────────────────────────────────────┘    ║
║                                                                             ║
║  Layer 5: ENCRYPTION AT REST                                                ║
║  ┌─────────────────────────────────────────────────────────────────────┐    ║
║  │  Vault Transit Engine: AES-256-GCM96                                │    ║
║  │  Auto-rotation every 30 days                                        │    ║
║  │  Deletion disabled (compliance)                                     │    ║
║  │  Batch encrypt/decrypt for performance                              │    ║
║  │  Fallback: local AES-256-GCM if Vault unavailable                   │    ║
║  └─────────────────────────────────────────────────────────────────────┘    ║
║                                                                             ║
║  Layer 6: DATA INTEGRITY                                                    ║
║  ┌─────────────────────────────────────────────────────────────────────┐    ║
║  │  HMAC-SHA256 on every document chunk                                │    ║
║  │  Stored in Qdrant payload alongside vectors                         │    ║
║  │  Verified at query time for tamper detection                        │    ║
║  │  Deterministic doc IDs (SHA256 of content)                          │    ║
║  └─────────────────────────────────────────────────────────────────────┘    ║
║                                                                             ║
║  Layer 7: AUDIT LOGGING                                                     ║
║  ┌─────────────────────────────────────────────────────────────────────┐    ║
║  │  structlog → JSON → file/SIEM                                       │    ║
║  │  Logged: user_id, query_hash, role, department, tenant              │    ║
║  │          auth_decision, confidence, answer_length, timestamp        │    ║
║  │  Query text stored as SHA256 hash (never plaintext in logs)         │    ║
