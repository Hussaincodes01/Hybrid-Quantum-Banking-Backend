## 1. Data Source Map

Every data field in FINIX comes from exactly one of three sources:

| Source | Symbol | Description |
|--------|--------|-------------|
| **Android App** | `📱` | User input collected on the Flutter client and sent to the backend |
| **Mock Bank API** | `🏦` | Financial data from the bank adapter (balances, transactions, verification) |
| **Backend-Computed** | `⚙️` | Derived by the Go backend from other data (ML scoring, risk signals, aggregates) |

## 2. Android → Backend API Contract

All calls route through `ApiClient` (Dio). The `AuthInterceptor` injects:
- `Authorization: Bearer <jwt>` on every authenticated request
- `X-Device-Fingerprint` on every request
- `Idempotency-Key` (UUID) on every POST/PATCH/DELETE

### 2.1 Authentication

| Endpoint | Method | Auth | Rate Limit | Request Body | Response |
|----------|--------|------|------------|-------------|----------|
| `/v1/auth/register` | POST | No | 10/min | `{ name?, mobile, email?, deviceIdFingerprint, deviceType?, appVersion? }` | `{ userId, ubt }` |
| `/v1/auth/ekyc/verify` | POST | No | 20/min | `{ userId, panLast4, aadhaarLast4 }` | `{ id, name, ekycVerified, kin }` |

| `/v1/auth/login/verify` | POST | No | 20/min | `{ userId, challengeId, signature, keyId, deviceIdFingerprint }` | `{ accessToken, expiresInSeconds }` |

## 3. Mock Bank REST API (OpenAPI 3.0)

This is the HTTP schema the mock bank should expose when running as a standalone service. It maps 1:1 to the `BankAdapter` interface in `internal/domain/platform/bank_adapter.go`.

```yaml
openapi: 3.0.3
info:
  title: FINIX Mock Bank API
  version: 1.0.0
  description: |
    Simulated bank API for FINIX dev/test. Implements the BankAdapter
    interface as a standalone HTTP service. 8 seeded accounts with
    deterministic data for offline demo.

servers:
  - url: http://localhost:9090/api/v1
    description: Local mock bank

paths:
  # ── UPI Verification ──────────────────────────────────────
  /verify/upi:
    post:
      operationId: verifyUPI
      summary: Verify a UPI ID and resolve the holder name
      description: |
        Maps to BankAdapter.VerifyUPI().
        Returns holder name for known UPIs, not_found for unknowns.
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required: [upiId]
              properties:
                upiId:
                  type: string
                  description: UPI ID to verify (e.g. "jiyad@sbi")
                  example: "jiyad@sbi"
      responses:
        '200':
          description: Verification result
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/UPIVerification'
              examples:
                known:
                  summary: Known UPI
                  value:
                    status: verified
                    holderName: Jiyad
                    verified: true
                unknown:
                  summary: Unknown UPI
                  value:
                    status: not_found
                    holderName: ""
                    verified: false
        '400':
          $ref: '#/components/responses/BadRequest'

  # ── IFSC Verification ─────────────────────────────────────
  /verify/ifsc:
    post:
      operationId: verifyIFSC
      summary: Verify IFSC code + account number pair
      description: |
        Maps to BankAdapter.VerifyIFSC().
        Two-step in production: IFSC resolves bank/branch, penny-drop confirms holder.
      requestBody:
        required: true
        content:
          application/json:
            schema:
              type: object
              required: [ifsc, accountNumber]
              properties:
                ifsc:
                  type: string
                  description: IFSC code (e.g. "SBIN0001234")
                  example: "SBIN0001234"
                accountNumber:
                  type: string
                  description: Account number
                  example: "12345678901"
      responses:
        '200':
          description: Verification result
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/IFSCVerification'
        '400':
          $ref: '#/components/responses/BadRequest'

  # ── Account Balance ───────────────────────────────────────
  /accounts/{accountId}/balance:
    get:
      operationId: getBalance
      summary: Get available balance for an account
      description: |
        Maps to BankAdapter.GetBalance().
        accountId can be an account number or UPI ID.
      parameters:
        - name: accountId
          in: path
          required: true
          schema:
            type: string
          description: Account number or UPI ID
          example: "12345678901"
      responses:
        '200':
          description: Balance
          content:
            application/json:
              schema:
                $ref: '#/components/schemas/BalanceResponse'
              examples:
                known:
                  summary: Jiyad SBI account
                  value:
                    accountId: "12345678901"
                    balancePaise: 35000000
                    currency: INR
                    asOf: "2026-07-27T12:00:00Z"
                unknown:
                  summary: Unknown account
                  value:
                    error: "account not found"
                    code: "NOT_FOUND"
        '404':
          $ref: '#/components/responses/NotFound'

  # ── Bank Connection ───────────────────────────────────────
  /connections:
    post:
      operationId: connectBank
      summary: Establish a bank API connection for a user
      description: |
        Maps to BankAdapter.Connect().
        Creates or refreshes a connection record. In production this
        would initiate OAuth2 or AA consent flow.
      requestBody:
        required: true
        content:
          application/json:
            schema:
              $ref: '#/components/schemas/ConnectionRequest'
      responses:
        '200':
          description: Connection established
```

### 3.2 Mock Bank Behavior Notes

- **VerifyUPI**: Lowercases/trims input. Returns `("verified", holder, true, nil)` for known UPIs, `("not_found", "", false, nil)` for unknowns.
- **VerifyIFSC**: Uppercases/trims IFSC. Matches IFSC + accountNumber pair against seeded data.
- **GetBalance**: Matches by lowercased account number OR UPI ID.
- **Connect**: Creates in-memory connection record. Preserves existing `connectionId` on reconnection.
- **FetchTransactions**: Returns user-specific events recorded by `SubmitPayment`. Falls back to 2 seeded events when empty.
- **SubmitPayment**: Validates `amountPaise > 0`, checks balance, debits, records `BankTransactionEvent` for later retrieval.
- **No randomization**: All amounts and counterparties are deterministic. Only IDs use `randomHex`.

### 4.1 Fraud Detection XGBoost (ONNX)

| Property | Value |
|----------|-------|
| **Type** | XGBoost multi-class (3-class), exported to ONNX |
| **Source** | `internal/domain/transaction/risk_engine.go`, `onnx_predictor.go`, `heuristic.go` |

| **Training** | `ml/train_fraud_model.py` (50K synthetic samples, `n_estimators=300, max_depth=6`) |

**Input Features (9):**

| # | Feature | Type | Range | Data Source |
|---|---------|------|-------|-------------|
| 0 | `amountVsAverage` | float32 | [0, 25] | ⚙️ Backend: `amountPaise / historicalAverageAmount(txHistory)` |
| 1 | `isNewRecipient` | float32 | {0, 1} | ⚙️ Backend: `!beneficiaries[userID].contains(recipient)` |
| 2 | `hourOfDay` | float32 | [0, 23] | ⚙️ Backend: `time.Now().UTC().Hour()` |
| 3 | `failedPinAttempts` | float32 | [0, 5+] | 📱 Android: `req.FailedPINAttempts` |
| 4 | `velocityCount1Hr` | float32 | [0, N] | ⚙️ Backend: count of txns in last 60min |
| 5 | `balanceImpact` | float32 | [0, 1] | ⚙️ Backend: `amountPaise / sum(account.BalancePaise)` |
| 6 | `recipientGnnScore` | float32 | [0, 1] | ⚙️ Backend: `fraudGraph.GetRiskScore(recipient)` |
| 7 | `behaviourDrift` | float32 | [0, 1] | 📱 Android: `req.BehaviourDrift` (client-computed) |
| 8 | `sessionTrustScore` | float32 | [0, 1] | 📱 Android: `req.SessionTrustScore` (client-computed) |

**Output:** `[]float32` of length 3: `[P(low), P(medium), P(high)]`

**Score mapping:** `score = P(medium)*50 + P(high)*90 + P(low)*10`, clamped [0, 100]

**Level:** `>= 70 → high`, `>= 40 → medium`, else `low`

### 4.2 Fraud Heuristic Predictor (Fallback)

| Property | Value |
|----------|-------|
| **Type** | Weighted rule-based scoring |
| **Source** | `internal/domain/transaction/heuristic.go:48-131` |
| **Availability** | Always (no ONNX binary required) |

**Formula:**
```
score = 0
if AmountVsAverage > 1:  score += clip((amountVsAvg - 1) * 12, 0, 30)
if IsNewRecipient:       score += 15
if HourOfDay <= 4 or >= 23: score += 10
if FailedPINAttempts > 0: score += min(failedPINAttempts * 5, 15)
if VelocityCount1Hr >= 3: score += min(velocityCount1Hr * 2, 10)
if BalanceImpact > 0.8:  score += 10
if BalanceImpact > 0.5:  score += 5
if RecipientGNNScore > 0: score += min(gnnScore * 20, 20)
if BehaviourDrift > 0:   score += min(drift * 20, 20)
if SessionTrustScore < 0.4: score += 15
if SessionTrustScore < 0.7: score += 8
score = min(score, 100)
```

**Output:** Same `Assessment` struct as XGBoost model.

| Property | Value |
|----------|-------|
| **Type** | N-hop risk propagation on in-memory directed graph |
| **Source** | `internal/domain/fraud/gnn.go:1-460` |

**Input:**
- Graph built from `AddTransaction(from, to, amountPaise)` calls

## 5. BankTransactionEvent Field Provenance

The `BankTransactionEvent` struct (`internal/domain/platform/aiml.go:108`) mixes
bank-originated fields with FINIX-computed risk signals. This table shows which is which.

### 5.1 Bank-Originated Fields (provided by real bank webhook/API)

| Field | Type | Description | Mock Populates? | Real Bank Provides? |
|-------|------|-------------|-----------------|---------------------|
| `EventID` | string | Unique event ID | ✅ `"mockevt_" + randomHex(6)` | ✅ Bank UTR/ref |
| `BankCustomerID` | string | User's bank customer ID | ✅ Mapped to `userID` | ✅ Bank internal ID |
| `BankAccountID` | string | Bank account identifier | ❌ (zero value) | ✅ Account identifier |
| `AmountPaise` | int64 | Transaction amount | ✅ Seeded or payment amount | ✅ Exact amount |
| `Counterparty` | string | Payee/payer identifier | ✅ UPI ID or name | ✅ VPA + name |
| `Channel` | string | Payment method | ✅ `"upi"` (hardcoded) | ✅ UPI/NEFT/IMPS/RTGS |
| `EventTimestamp` | time.Time | Transaction time | ✅ `time.Now()` or offset | ✅ Bank timestamp |
| `Source` | string | Data origin | ✅ `"mock-bank"` | ✅ `"bank_api"`, `"aa"`, `"webhook"` |
| `Metadata` | map[string]any | Enrichment data | ❌ (nil) | ✅ MCC, narration, UTR, etc. |

### 5.2 FINIX-Computed Fields (attached at ingestion boundary)

| Field | Type | Description | Computed By |
|-------|------|-------------|-------------|
| `DeviceTrustScore` | float64 | Client-side device attestation score | `AuthInterceptor` → `RiskSignal` |
| `BehaviourDrift` | float64 | Deviation from established behaviour pattern | Client-side ML or `PredictBehaviour()` |
| `FailedAuthAttempts` | int | Failed authentication count | `AuthService` (partially bank-sourced) |
| `IsSynthetic` | bool | Whether this is a synthetic/test event | `SubmitPayment()` in mock bank |

### 5.3 Key Observation for Real Integration

> A real bank webhook would only provide the 9 bank-originated fields. The 4
> FINIX-computed fields must be attached at the `IngestBankEvent` boundary layer
> from client-side device attestation and session data — NOT from the bank payload.
>
> The mock bank currently populates 6 of 9 bank-originated fields (missing
> `BankAccountID`, partial `Metadata`). A real integration needs:
> 1. `BankAccountID` mapping from the connection record
> 2. `Metadata` enrichment with MCC codes, narration, UTR
> 3. FINIX-computed fields injected from the device trust layer
